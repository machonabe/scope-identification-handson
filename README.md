# 市場品質不具合の対象範囲特定 ハンズオン（Databricks Free Edition・45 分）

> このリポジトリのデータ（車種名・型式・VIN・部番・部署名・会社名・依頼書）は、すべて架空の合成データです。実在する企業・製品・様式とは関係ありません。

調査依頼書（Excel）を受け取ってから、回答用リスト（措置号機対象リスト）を出すまでの流れを、Databricks 上で一通り動かします。
今は複数の部門が車歴・部品表・各種マスタを個別に調べ、Excel で突き合わせている作業を、**1 つの場所のデータで、上から順に自動で判定する**形にします。

- 扱う工程：① 依頼書取込 ② 条件自動生成 ③ 号機特定（概算VIN） ④ 対象期間特定 ⑤ マスタ照合 ⑥ 対策適応判定 ⑩ 対象確定 ⑪ 帳票出力
- 結果は最後に **業務の画面（Databricks Apps）** で確認します：案件管理・ダッシュボード・ステップ表示・検索・レポート出力
- 扱わない工程：⑦ 点検改修 ⑧ Lot崩れ ⑨ 打刻No飛び

## 時間割（45 分）

| 時間 | ノートブック | 内容 |
|---|---|---|
| 0〜5 分 | （説明） | 今の作業と、このハンズオンで自動化する範囲 |
| 5〜10 分 | `01_データ準備` | 合成データと調査依頼書（Excel）を作る |
| 10〜17 分 | `02_依頼書取込と条件生成` | ① 依頼書を読み取って案件登録 → ② 特定条件に翻訳（あいまいな記載は要確認） |
| 17〜25 分 | `03_号機特定と対象期間` | ③ 概算VIN を作る → ④ 対象期間を製造日の窓にする |
| 25〜32 分 | `04_マスタ照合と対策適応` | ⑤ イベント車・廃車・終了証の印 → ⑥ 初物の境界で対策適応済みの印 |
| 32〜38 分 | `05_対象確定と帳票出力` | ⑩ 上から順に判定して ●／× を確定 → ⑪ 回答用リスト（Excel）を出力 |
| 38〜43 分 | `07_アプリをデプロイ` | 結果を業務の画面（Databricks Apps）にデプロイして開く |

| 持ち帰り | `06_発展_最新データで再判定` | 遅れて届いた生産実績を取り込んで再判定 → 05 を再実行すると、アプリの版と台数が変わる |

## 準備（始める前に）

1. Databricks Free Edition にサインアップしてログインします。
2. 左の「ワークスペース」で自分のフォルダ（`/Users/<メールアドレス>`）を開き、右上の「作成」→「Git フォルダー」を選びます。
3. 「Git リポジトリの URL」に `https://github.com/machonabe/scope-identification-handson` を貼り付け、「Git フォルダを作成」を押します。公開リポジトリなので、Git の認証情報（トークン）の設定は要りません。
4. できたフォルダに、番号付きのノートブック 9 個（00〜07・99）と `config.yaml`・`README.md`・`app` フォルダ（`app.py`・`app.yaml`・`requirements.txt`・`static`）があることを確認します。
5. `config.yaml` の `catalog` が、左の「カタログ」に表示されるカタログ名（Free Edition では通常 `workspace`）と同じか確認します。

- ノートブックを実行・編集すると、Git フォルダには「変更あり」と表示されますが、そのままで構いません（ハンズオンでは commit や push はしません）。07 が作る `app/config.yaml` は `.gitignore` で対象外にしてあります。
- 講師がこのリポジトリを更新したときは、Git フォルダの画面で「プル」を押すと最新になります。
- Git フォルダを使わない場合は、講師から受け取った `scope_handson.zip` を、自分のフォルダの右上の「︙」→「インポート」で取り込みます。取り込んだフォルダに `config.yaml` が無いときは、「作成」→「ファイル」で `config.yaml` を作り、このリポジトリの内容を貼り付けます。

## 設定ファイル（config.yaml）

すべてのノートブックは、最初のセルの `%run ./00_config` で `config.yaml` を読み込みます。カタログ・スキーマ・ボリュームの名前はここだけで決まります。

| 項目 | 既定値 | 意味 |
|---|---|---|
| `catalog` | `workspace` | 保存先のカタログ |
| `schema` | `scope_handson` | このハンズオン用に作るスキーマ |
| `volume` | `files` | 依頼書・回答リスト・届いたデータを置くボリューム |
| `request_file` | `調査依頼書_REQ-2026-0001.xlsx` | 依頼書のファイル名 |
| `data.seed` / `data.vehicles_per_model_year` | `42` / `900` | 合成データの乱数の種と台数 |
| `ai_model` | `system.ai.gpt-oss-120b` | 02 の任意セルで使う生成 AI（使えなければ飛ばします） |
| `app_name` | `scope-handson` | 07 でデプロイするアプリの名前（英小文字・数字・ハイフン、26 文字まで） |

## 進め方

- ノートブックは番号の順に、上の「すべてを実行」で動かします。計算はサーバーレスで、各ノートブック 1〜2 分で終わります。
- 各ノートブックの最後に **確認ポイント** があり、うまくいけば ✅ が出ます。❌ が出たら、前のノートブックから実行し直してください。
- 回答用リストは、左の「カタログ」→ カタログ → `scope_handson` → ボリューム `files` → `outputs` からダウンロードできます。
- 05 は実行するたびに版（v1, v2, …）を増やして結果を残します。

## アプリ（07）

- `app/` にアプリのコードがあります（Python の FastAPI と、画面の HTML・JavaScript・CSS。追加のライブラリは使いません）。
- 07 は CLI を使わずに、①`config.yaml` を `app/` にコピー → ②アプリを作成（01 の最後で作り始めています）→ ③アプリのサービスプリンシパルにスキーマの読み取りとボリュームの読み取りを付与 → ④デプロイ、を行います。
- データはアプリのサービスプリンシパルの権限で、SQL ウェアハウス経由で読みます。
- 1 画面分の SQL はまとめて同時に実行し、取ったデータはページを再読み込みするまで使い回します（画面の切り替えやステップのクリックでは待ちません）。05 を実行し直したあとは、画面を再読み込みしてください。
- SQL ウェアハウスが止まっていると、最初の画面だけ 10〜20 秒かかります（画面にそう表示されます）。
- Free Edition のアプリは 1 アカウント 3 つまでで、起動から 24 時間で自動的に止まります。止まったら 07 をもう一度実行してください。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| `config.yaml が見つかりません` | ノートブックと同じフォルダに `config.yaml` を置く |
| `カタログ '…' がありません` | エラーに出たカタログ名のどれかを `config.yaml` の `catalog` に書く |
| `%pip install` が失敗する | 01・02・05 は Excel を扱うため最初に openpyxl を入れます。少し待ってから、そのセルをもう一度実行する |
| AI のセルでエラー | 任意のセルなので飛ばして進めてよい |
| 07 でアプリを作れない | Free Edition ではアプリは 3 つまでです。使っていないアプリを削除してから、07 をもう一度実行する（`app_name` をほかのアプリと同じ名前にしないでください。そのアプリが置き換わります） |
| アプリの画面で「データを読めませんでした」 | 07 の手順 3（権限の付与）を実行したか確認し、05 まで実行済みか確かめる |

## 後片付け

`99_後片付け` で、作ったスキーマ（テーブル・ビュー・ボリューム）とアプリをまとめて削除します。ウィジェットで「削除する」を選んだときだけ削除します。
